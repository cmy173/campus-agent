# 需求与优先级

P0 为首版闭环；P1 为闭环稳定后的增强；P2 为需平台合作或复杂处理的后续功能。下表是需求，不代表实现状态。

| 编号 | 场景与行为 | 优先级 | 依赖与验收重点 |
|---|---|---|---|
| R01 | Web 对话、移动适配、任务进度、失败提示 | P0 | API；每次回答显示来源与处理状态 |
| R02 | 导入通知、培养方案、课程 PDF/PPTX/DOCX/TXT | P0 | 文件校验、解析任务；保留页码/幻灯片号；扫描件明确不支持 |
| R03 | 从上传材料检索并回答，找不到时说明证据不足 | P0 | 用户隔离、段落索引、模型适配；引用可回到原文 |
| R04 | 通知摘要、截止时间、待办、来源去重 | P0 | 日期时区、内容版本；缺少时间不补造 |
| R05 | 活动推荐与剩余缺口 | P0 | 结构化活动与人工核对的规则；展示类别、资格、冲突与不确定性 |
| R06 | Mock Connector 与受控工具注册表 | P0 | 能力、权限、错误契约；未知操作拒绝 |
| R07 | 数据删除、审计、访问控制 | P0 | 多用户开放前必须完成；删除索引与原件一致 |
| R08 | 课程组合、先修与培养要求分析 | P1 | 年级/专业培养方案、已修课程、替代规则与课表 |
| R09 | 每日简报、增量同步、提醒 | P1 | 用户订阅、时区、队列、重试与通知通道 |
| R10 | 课程笔记、练习题、视频时间轴 | P1/P2 | 先处理字幕；音频转写必须有权限与预算 |
| R11 | 往届报告与教师反馈分析 | P1 | 明确评价、客观观察、AI 推测分栏；逐条引用 |
| R12 | 平台报名、表单及申请 | P2 | 合法写接口、具体确认、幂等、回执核验 |

## 合并后的基础能力

通知摘要、作业提取、课程笔记都依赖同一套资料解析与来源模型；活动与课程推荐共享时间冲突检测，但学分认定规则分开管理。简报复用通知和待办，不再建立第二套数据源。

## 隐藏依赖

浙大学期与周次、考试时间、校区通勤、活动认定类别及学生年级规则都影响推荐。当前未拿到经核实的规则，因此原型只演示抽象时间段与虚构学分，不能计算真实毕业缺口。

上传文件中的命令不构成用户授权。模型无法提升工具权限。平台故障时显示最后同步时间与失败原因，不能把缓存视为实时状态。

## 非功能要求

多用户版本所有资料、检索、缓存与任务均按服务端身份隔离；请求可追踪；日期保存带时区时间；耗时解析异步化；限制文件大小、页数和解析时长。中文日期歧义需用户核对。目标性能在真实语料与选定模型上压测后确定，不预报未经测量的延迟。
