# Campus Agent：以目标和工具为核心的重设计

日期：2026-10-13。状态：首轮 M0–M2 已在独立工作树完成验收；下列原设计保留为历史依据。V2 个人完整助手已完成规划，尚未启动实施。

下一轮以 [V2 个人完整助手执行合同](goal-v2-personal-assistant.md) 为准：统一新系统、迁移后退役旧代码、开放 C 档通用能力、复用 DeepSeek 官方接入，并为后续 UI 改版分层。首轮实际位置与报告见 [实施位置](../agent-progress.md)。

产品初心：减少学生获取、判断和组织校园信息的负担，让一个对话框成为大部分校园问题的共同入口。

本次已抓取远端全部分支；审阅对象包括最新 main 发布包内的学习工作台、最新功能分支，以及当前工作区的校园通知与教务增量。未切换、重置或覆盖已有未提交改动。

## 阅读顺序

1. [项目审阅与指导意见](review-2026-10-13.md)：版本现状、偏离初心的原因、应保留与调整的能力。
2. [产品与技术设计](product-and-architecture.md)：对话主入口、上下文工作区、Agent 编排、数据与权限、实施和验收。
3. [工具目录与使用文档](tools.md)：将现有流程拆成明确、有边界的工具，逐项说明映射与使用方法。
4. [典型任务编排手册](workflows.md)：学生的一句话如何变成工具调用，以及异常时如何继续。
5. [DeepSeek Harness 接入方案](deepseek-harness.md)：直接复用运行时的范围、校园插件、Python 桥接、调用方式与接入验收。
6. [机器可读工具索引](tools.index.json)：36 个工具的稳定名称、模型名称和实现依据；不是可执行注册表或完整 JSON Schema。
7. [持续实施 Goal 提示词](goal-implementation-prompt.md)：首次启动与接续命令、通用模板、M0–M2 执行合同、验收与阻碍处理，以及下一轮 Goal。

核心决策：复用现有业务能力，在它们上方增加统一工具层和有限步骤的 Agent 编排；学生表达目标，系统承担选择数据源、检索、整理和组合的工作。课表、资料、计划和复习卷成为对话可打开的工作区。

运行时建议：优先采用用户指定的 DeepSeek Harness，以独立运行时和校园工具插件接入现有 Python 服务。产品设计中的编排层是逻辑职责，不要求重写 Harness 已有的循环、会话和工具执行机制。上游仍需固定版本并完成接入验证。

这里的工具名是拟议的稳定契约，**不是声称这些函数或 MCP 工具现在已经可调用**。现有 HTTP 路由是实现依据；新工具层的身份校验、返回封装、上下文与授权仍需开发。该设计不要求先采用 MCP，也不要求重写现有引擎。
