# 典型任务编排手册

本手册供产品、Agent 提示词和实现测试共同使用。工具名见 [目录](tools.md)，以下为设计流程，并非现有软件已经支持。具体调用必须由真实工具结果驱动，示例不得作为预置学生事实。

## 1. “今天有什么要紧事？”

1. 运行时提供当前日期和 Asia/Shanghai 时区；查询 `connections.status`。
2. 独立读取 `assignments.list`、`tasks.list`、`plans.read`；校园适配可用时加入 `campus.query(courses/college_notices)`。
3. 按稳定来源关联去重，保留“作业截止”“课表”“本地计划”“通知候选”的类型区别。
4. 确定性逻辑排出当天课程、临近截止、未核对但可能重要的事项；模型负责简洁说明及推荐理由。
5. 默认展示最重要的三项与总覆盖范围，用户可展开全部。

失败处理：一平台过期时展示其他已知信息，并说“某平台尚未更新，清单可能不完整”；有数据但未生成计划时仍回答截止事项。只缺少一个连接，不重跑全部同步。

验收：跨平台同一作业不重复催办；平台已提交不当未交；未知截止保留为待核对；不能把前三项当完整清单。

## 2. “这份通知到底要我做什么？”

1. 从当前卡片确定通知 ID；无上下文时从 `campus.query(college_notices)` 获取候选。
2. 已保存通知直接读现有分析；需要保存时按本轮授权调用 `notices.import`，再用 `notices.analyze`。
3. 依次输出：适用对象、需要做的动作、明确截止、地点、官方入口、原文依据。
4. 附件未解析时明确缺口，并提供已有官方附件链接。不能为了填满卡片编造时间或资格。

失败处理：模型不可用时保留原文与规则结果，说明哪些字段未确定。不能要求学生理解“tokens”“证据更正计数”等内部字段。

验收：发布日期不当截止；活动开始不当报名截止；通知相关性不等于用户已符合资格。当前工具集不提供通知候选确认写入，第一阶段以解释和核对为闭环，后续再接该动作。

## 3. “实验报告什么时候交？还要交哪些材料？”

1. `courses.list` 解析课程；仅同名歧义时询问。
2. `assignments.list` 查结构化截止和提交状态；`materials.search` 查要求。
3. 对命中条件调用 `materials.read` 读上下文，返回材料清单与出处。
4. 学校作业与上传通知冲突时并列来源、更新时间和冲突，不能靠模型任选一个日期。

验收：资料没有正文时不根据标题总结；日期有日无时就保持日期精度；引用能打开到正确版本/段落。

## 4. “这周帮我安排一下，周三晚上没空”

1. `tasks.list`、`assignments.list`、`availability.read`、`plans.read` 获取事实与既有安排。
2. 缺学习任务且用户确实要整理任务时调用 `tasks.build`；用 `jobs.read` 等待并重读。
3. 将“周三晚上没空”解析为本轮约束；现有排程接口不支持临时例外时，需先开发约束适配，不能悄悄把永久偏好改掉。
4. `plans.preview` 返回候选、锁定块、无法排入的任务与变更差异。
5. 用户接受具体方案，或既有明确授权覆盖该方案时，调用 `plans.apply`；随后 `plans.read` 核验生效。

失败处理：容量不足时说明缺多少时间和建议取舍，不超出用户时间安排；预览过期时重算并让用户看到变化。单个课程同步失败不删除既有计划。

验收：“帮我安排”得到可检查方案；“就按这个来”解析为同一 plan ID 和 input_revision；重复应用不造成两个生效方案。

## 5. “刚才那个任务做完了，把剩下的挪到明天”

1. 从会话上下文解析 task ID；有多个候选才询问。
2. `tasks.feedback(completed)`，获取实际写入结果。
3. 读取当前计划和剩余任务，检查明天可用时间；支持临时约束后调用预览。
4. 只展示剩余安排的差异，遵循用户指令范围应用；超出可用时间则返回具体取舍，不虚报安排完成。

验收：本地完成不修改平台提交事实；重发消息不重复反馈；已有锁定安排不会被静默挪动。

## 6. “用第三章课件出一份适合半小时练习的卷子”

1. `courses.list` 确定课程，`reviews.list` 检查已有产物。
2. `reviews.materials` 查材料；必要时通过 `materials.search/read` 核实第三章内容范围。
3. 缺材料则就地允许上传，`materials.import` 后查询 job；不跳转多个设置页。
4. `reviews.preview` 展示所用材料、题型/题量建议、外发模型与缺口。半小时是目标，不承诺题目耗时精确。
5. 满足既有授权和预算后 `reviews.generate`，返回进度卡。
6. 完成后 `reviews.read` 在工作区展示；“简单一点”通过重新预检与 `reviews.revise` 形成新版本；需要文件时 `reviews.export`。

失败处理：材料版本变化重做预检；后台运行失败保留旧卷。用户取消时调用 `jobs.cancel`，显示真实最终状态，不保证已产生费用退款。

验收：预览内容与实际发送快照相同；不会因为网络超时重复扣费生成；阅读试卷不需要继续用聊天逐题展开。

## 7. “上节课老师怎么讲这个概念的？”

1. `courses.list`、`recordings.list` 确定课程与场次；“上节课”须结合场次时间，不能简单取列表第一条。
2. `recordings.transcript` 读取该场字幕；按长度分段，附时间戳。
3. 找到相关解释后给简短总结和跳转位置；字幕不清晰时说明限制。

失败处理：没有可用字幕即说明未覆盖，可继续检索已有课件；不能声称已观看视频，或调用并未接入的板书/音频模型。

## 8. 通用恢复与运行边界

| 情况 | Agent 行为 |
|---|---|
| 没有连接 | 先回答已有资料能覆盖的部分，按任务提示一个必要连接 |
| 会话失效 | 就地出现官方登录入口；保存任务进度，登录后从失败步骤继续 |
| 上游限流 | 遵守 retry_after，保留缓存与时间，不自动切账号或重复登录 |
| 缺少证据 | 说明缺少的具体材料；不把一般常识写成校方规定 |
| 用户中途修改目标 | 取消/保留对应 job 按用户意图处理，旧结果不能覆盖新请求 |
| 已发起写入但连接断开 | 先按 request_id/幂等键/job 查询，不重新执行相同副作用 |
| 删除资料或退出 | 失效上下文、引用及后续回调；新账号不能继承旧结果 |

这些是可测试的工作流规范。工作流文档指导模型选工具，不授予任何额外权限；运行时与业务服务必须独立校验每一步。
