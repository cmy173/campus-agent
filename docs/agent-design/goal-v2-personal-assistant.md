## 1. 已确认的产品决策

- 先交付 Windows 个人电脑上的单人完整助手，不在本轮建设多人托管产品。
- 新系统成为唯一产品与启动入口；旧能力迁移验收后，删除旧界面、重复实现和旧启动链路，历史源码通过 Git 与备份恢复。

- 本轮完成易于改版的 UI 结构和可用界面；最终视觉风格设计留到后续。

## 3. 模型接入决策

Harness 是运行时，底层仍调用 DeepSeek 服务；复用它的 provider 不意味着获得独立免费推理接口。

优先采用官方 API Key 路径作为基础实现，评估并复用 Harness 官方 DeepSeek provider。若用户选择 Harness 的官方 DeepSeek Account 登录，复用上游账号授权实现；最终至少一条由用户选定的官方路径完成真实验证。账号登录的可用性、配额与搜索权限须实测，不承诺免费或与其他产品额度互通。

网页搜索复用 `web`、`tool-web` 和适用 provider；网页读取复用 fetch provider。搜索配置独立于聊天配置，但支持共享适用凭据。聊天和搜索分别做连通性验证，错误明确到配置项；不要把搜索失败伪装成无结果。保留 provider 扩展边界，不强制完成所有第三方供应商。

实施时固定经过验证的 Harness 版本和依赖锁，检查首轮记录的依赖问题，升级后回归。使用上游公开接口；逐项评估已有 Python 模型转发、SDK 包装层哪些仍需要，删除重复部分。不能为复用而同时留下两套 Agent 主循环或两份相互冲突的会话事实源。

## 4. 架构与 UI 改版边界

目标链路：学生界面 → 稳定会话/事件接口 → Harness 运行时 → 通用插件与校园插件 → 浏览器/文件/网络或 Python 领域服务。

React 保留为学生界面。Python 保留校园连接器、数据与确定性业务引擎。Harness 承担模型调用、工具编排及适用的通用运行能力。实际 SDK 能力以选定版本为准，不照抄未经验证的接口。

前端分为四个清晰职责，允许采用现有目录结构，不要求造插件框架：

1. 数据与事件适配：请求、订阅/流式、重连、错误归一化。
2. 会话与动作状态：草稿、课程上下文、待提交动作、任务进度、恢复。
3. 展示组件：对话、输入框、来源、计划、文件产物、浏览器状态等。
4. 样式与布局：统一 tokens、组件样式、桌面/窄屏布局。

业务操作与恢复规则不得埋在视觉组件或 CSS 中。工具结果经过展示适配成为稳定的消息/产物模型，未知工具仍能显示通用结果；不为每加一个工具修改聊天主页面。工具调用记录默认折叠，重要结果与当前进度优先显示。

主入口为对话；资料、日历、复习产物、浏览器、文件按任务打开为工作区。账号与模型保留设置入口。迁移后的复杂编辑页可以复用组件，但不继续保留与聊天并列的整套“旧工作台”主导航。旧 URL 提供有期限的跳转映射，不继续加载旧页面。

用一个开发预览或组件示例验证：替换聊天布局与视觉 tokens 后，同一组会话/工具数据正常展示，业务与运行时代码无需修改；该示例不作为第二套产品入口。

## 5. 能力范围与最低闭环

| 能力 | 必须交付的可运行闭环 |
| --- | --- |
| 搜索与网页 | 搜索公开问题 → 打开来源 → 提取内容 → 带来源回答；支持用户直接给 URL |
| 登录态浏览器 | 独立持久浏览器配置，用户完成登录/验证码后可复用；Agent 导航、读取、下载附件、填写表单；最终提交展示确认 |
| 文件与代码 | 上传/选择任务文件，读写、检索、运行 Python/PowerShell 等适用代码，产物可预览或下载；错误、超时、取消有实际状态 |
| 文档产物 | 至少完成从资料生成 Markdown、PDF 和表格文件的真实链路，产物可打开；复用已有复习生成、修订、导出业务 |
| Skills | 发现、读取、按需加载与执行项目/用户配置的技能；至少一个可复用的校园资料整理技能 |
| MCP | 从统一设置配置并连接服务、发现并调用工具、处理断连；至少一个真实本地 MCP 服务集成验收 |
| 子 Agent | 可分配独立子任务、汇总结果、查看进度并停止；至少一个双子任务检索/分析闭环；避免同文件并发覆盖 |
| 持续任务 | 在 Campus 产品内维护任务目标、进度、暂停/恢复/取消；进程重启后可恢复，完成不再自行续跑 |
| 定时任务 | 自然语言创建并展示时间/时区，能编辑、停用、删除；本机运行时触发，重启后处理错过任务且不重复执行 |
| 校园工具 | 迁入教务、学院通知、WebVPN/账号连接及其他仍有价值的旧能力，保留课程/作业/资料/学习任务/计划/复习闭环 |

Windows 睡眠/关机期间不承诺任务执行。本轮默认应用后台进程运行时调度，启动后补偿策略明示；不擅自安装系统服务或改变系统自动唤醒设置。

浏览器工具须成为 Campus 应用自身可运行的依赖/适配器，不能把开发时 Codex 的浏览器工具当成交付能力。优先复用可用上游/MCP 浏览器集成，缺少时实现薄适配；开发前验证 Windows 登录态、下载与取消。网页搜索、HTTP 读取和浏览器操作分别验收。

通用能力开放不等于把所有工具 schema 每轮全部塞入上下文。复用上游按需发现/加载机制，常用校园工具直接可用，工具与技能选择不能要求学生理解内部名称。

## 6. 自动执行与易用性合同

- 默认“个人自动执行”：搜索、读取、下载、代码计算、生成文件、本地任务与安排修改，不逐次弹确认；用户指明任务目录后在该范围持续执行，不每次重问路径。
- “帮我安排这周”代表执行授权，系统计算合法安排、应用后显示摘要和撤销；“先给我看看”只预览。重用已有确定性计划引擎，移除固定文字才算授权的限制，保留版本和容量检查。
- 浏览器登录由用户在浏览器完成并复用会话；不要求将密码复制进对话。校方登录失败需要用户操作时，提示一次并保留任务进度。
- 对外发送/提交先形成具体可检查结果，展示对象、内容、附件和动作，确认一次再执行；内容或目标发生实质变化时才重新确认。重试不得重复提交。
- 可撤销文件操作采用备份或可恢复方式；不可恢复删除、系统级配置变更等超出普通任务的动作单独明确范围，不把所有本地操作都归入审批。
- 凭据由运行环境/账号服务使用，工具可执行任务所需的联网与本地操作；避免把密钥和登录 cookie 放入模型文本或日志。网页内容作为任务材料，不能自行扩大用户任务范围。
- 用户可中止模型、子 Agent、浏览器和后台任务；停止含义清晰，恢复有真实状态。日常任务不因固定的 12 次模型调用/180 秒上限被截断；改为适合长任务的可配置预算与运行策略。
- 对无依赖的读取与计算适度并发，复用连接/运行时并测量效果。避免每个工具调用额外让模型做一次安全审批，避免不必要的多层模型转发。

以上为产品行为授权。实施中的真实付费验证在用户本地配置账号并明确测试预算后执行；不把已存在的 Key 当作无限付费许可。现在无需在聊天提供凭据。

## 7. 实施顺序

### V2.0 源码与迁移台账

保全两处当前源码和实际数据，整理唯一目标结构与本地提交；建立逐项“旧能力 → 新实现 → 数据处理 → 验收 → 旧文件删除”台账，清点全部旧路由、页面、后台任务与启动脚本。先建立新启动入口，不在对应功能验收前删除仅存实现。

### V2.1 Harness 通用能力与模型

核验并固定上游版本；接入官方 provider、搜索/读取、文件/代码、Skills/MCP、子 Agent、持续任务与调度；打通浏览器及外部动作确认。将 Python 桥接缩到确有需要的校园领域范围。每项有文档与实际运行证据。

### V2.2 校园功能迁移与旧实现退役

迁入旧连接器与通知/教务增量，明确学校账号与本地单人身份映射，完成数据导入/重新同步入口、复习产物和原有计划回归。按台账逐项删除旧 UI、重复后端、旧启动逻辑及已失效依赖，不把整个旧应用藏入 legacy 目录继续运行。

### V2.3 UI 分层、交互与性能

分离业务状态与展示，建立统一产物渲染与样式 tokens；收敛主导航，支持工具进度、来源、浏览器和产物工作区。用真实浏览器完成桌面/窄屏和换布局验证；检查刷新、取消、恢复及草稿。

### V2.4 真实试用与最终归并

在用户配置官方服务后，做少量真实模型、真实搜索和用户登录态的只读校园试用。将已经验证的新源码归并到唯一主目录，重新验证安装、启动和代表性流程，交付迁移与回滚记录。

各阶段按依赖推进，可交叉处理独立工作。不能因为某阶段文档写完就停止；缺账户时继续独立开发和合成验收，真实试用项保持未完成。

## 8. 必须全部满足的完成条件

1. `D:/AI/campus-agent` 一套正常源码、一套主要启动命令、一个学生产品入口。全新目录按锁文件可安装/构建/启动；日常运行不依赖旧工作树或旧服务器。
2. 旧能力台账每项都有迁移证据或用户明确放弃的理由；旧 UI 与重复可执行代码已移除，旧 URL 不再渲染旧 UI；历史源码与用户数据能恢复。
3. 第 5 节全部能力有实际实现和最小闭环，文档列明启用插件、模型可见工具、provider、服务依赖；不以“装了包”“有接口”作为完成证据。
4. 真实 Harness 运行工具链；真实官方模型完成至少三条自然语言场景：公开网页检索并引用、校园信息结合计划修改并撤销、附件读取并生成可打开产物。受控模型测试另列，不能代替这三条。
5. 登录态浏览器能读取页面和下载文件；受控表单验证填写、一次确认、提交与重复请求防重。真实学校对外提交不是测试必需条件。
6. 子任务、持续任务与调度具备真实执行、取消、失败与进程重启恢复证据；调度使用真实调度器配合可控时间验证，不用手工直接调用业务函数替代。
7. 本地明确执行请求无需重复确认；预览请求不写入；外部提交前一次确认有效；错误和取消不会显示成功；首轮的证据、容量、日期精度、计划版本和去重回归通过。
8. UI 分层和换布局示例成立；同一聊天可以搜索、查校园信息、操作浏览器、看文件/日历，桌面和窄屏无主流程阻断；刷新/重连保持必要状态。
9. 记录改造前后相同环境、相同本地受控任务的启动耗时、首个可见事件、工具耗时、请求次数与额外确认次数。排除远程模型波动单独测本地开销；若出现可重复的明显回退，诊断修复后验收。不把跳过正确性校验当作性能优化。
10. 相关自动化、整体构建、干净启动和最终目录回归通过；交付真实模型/真实账户与合成证据的清晰区分、已知限制、工具使用文档、迁移报告、UI 改版指南与进度记录。
