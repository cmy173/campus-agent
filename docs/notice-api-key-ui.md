# 通知整理模型 API Key UI 配置

## 功能说明

在设置页面添加了 DeepSeek API Key 的临时输入框，允许用户在不重启服务器的情况下配置模型密钥。

## 使用方式

1. 登录系统后，进入"隐私与设置"页面
2. 在"通知整理模型"部分，如果未检测到环境变量中的 `DEEPSEEK_API_KEY`，会显示输入框
3. 输入你的 DeepSeek API Key（以 `sk-` 开头）
4. 点击"保存（仅本次会话）"按钮
5. 配置立即生效，可以用于通知整理事件提取

## 安全特性

- **内存存储**：API Key 仅保存在服务器进程的内存中，不写入数据库或文件
- **会话隔离**：每个用户账号有独立的密钥存储空间
- **自动清除**：重启服务器后所有运行时密钥都会被清除
- **不暴露密钥**：前端无法读取已保存的密钥，只能看到配置状态
- **优先使用**：运行时配置的密钥优先于环境变量

## 技术实现

### 后端 (web.py)

- 添加 `runtime_api_keys` 字典存储各用户的运行时密钥
- `/api/model/configure` POST 端点用于保存/清除密钥
- `/api/model` GET 端点返回包含运行时密钥状态的配置信息
- `NoticeAnalysisService` 的 extractor factory 闭包可以访问运行时密钥

### 前端 (app.js + index.html)

- 设置页面添加密码输入框和保存/清除按钮
- `loadSettings()` 根据配置状态显示/隐藏输入区域
- 保存成功后清空输入框并刷新配置状态
- 提供明确的用户反馈（toast 消息）

### 模型适配器 (notice_model.py)

- `configuration()` 和 `extractor()` 函数支持可选的 `runtime_key` 参数
- 运行时密钥优先于环境变量 `DEEPSEEK_API_KEY`
- 保持原有的错误处理和分类逻辑不变

## 测试验证

所有现有测试通过（43 个 Python 测试），包括：
- 配置端点不泄露密钥
- 运行时密钥正确传递给 extractor
- 失败重试时保留上一次结果
- 并发请求处理

## 注意事项

1. 此功能主要用于开发和本地试用场景
2. 生产环境建议使用环境变量或密钥管理服务
3. 输入框只在未配置环境变量时显示
4. 密钥格式验证由 DeepSeek API 服务端完成
