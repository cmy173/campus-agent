# 项目愿景

版本：2026-10-08，v0.2 本机原型。依据当前 8 页说明，浙江大学是唯一目标高校。

Campus Agent 为浙大学生整合通知、学习资料和事务上下文，将“在多个系统查找信息”转为“提出目标，得到可追溯答案和可检查建议”。未来执行事务必须有合法接口、具体授权及结果核验。

## 用户与首个场景

首批试点建议选择一个院系、同一年级的 5–10 名志愿学生，此为招募建议而非已有用户。首个问题是“我上传的通知里有哪些事项快截止了？”其次是“根据这些活动资料，我有哪些不冲突的选择？”

产品与导航站的区别是整合来源、提取约束、给出行动建议；与通用聊天工具的区别是用户数据权限边界、资料引用和可验证工具调用。初期不承诺毕业资格判断、实时席位或自动办理。

## 成功判断

试点前后记录整理一组通知的耗时、遗漏截止事项数与引用正确率。先验证用户是否节省时间，再扩展平台连接。质量目标与验收方法见 mvp.md，所有目标均非已测产品指标。

## 范围边界

MVP 只服务浙大，保留业务与连接器的代码分离。原始资料始终高于模型推断；来源不足时说明缺失。课程资料处理以用户有权使用为前提，材料可访问不等于可以公开传播。
