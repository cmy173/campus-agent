# 校园模块整合审查（2026-10-11）

本次结果位于 feature/campus-integration，未合并或修改 main。

## 选择与取舍

审查来源：codex/zju-passport（21e64f0）、feat/campus-passport-login（bf4a2b6）、feature/portable-launch（6fddbf8）。

采用 codex/zju-passport 的通行证、教务/ETA 适配、缓存、校历、课表与成绩看板。它包含固定站点范围、浏览器绑定的短期登录流程、一次密码提交、业务权限探测、数据来源及失败保留缓存，适合继续完善。合入通用安装启动程序，保留原账号显式绑定机制。

未叠加另一个分支的 passport.py：两套认证入口职责重叠。较小分支只用重定向中的 ticket 判断成功，返回提交的账号标识，没有完整业务权限探测；它还替换本地登录。混用会造成会话与身份模型不一致。其失败不自动重试、不保存密码的原则已由选用实现覆盖。

## 修复

- 完整分支的界面只提供通行证与旧账号登录，新用户无法在校园服务不可用时试用。增加“本地试用 / 注册”，复用现有隔离的本地账号接口；不把本地注册当作校园身份认证。
- 周次与单双周字段均缺失时，原实现假设每周上课。现在保留原始记录并放入待核对列表，不计入按日期计算的今日课程或冲突；有明确周次的课程照常展示。
- 同步安装文档、分支下载命令与功能边界，保留通用启动和原有资料功能。

## 验证与限制

整合后 160 项 Python 合成测试通过；四个前端脚本语法检查通过。另有 Node 前端行为回归验证本地注册与登录使用不同接口、输入密码及时清空。没有向学校提交真实凭据，没有使用真实 API Key。

上游文档记录过本人账号联调；本次未独立复验该记录。校历默认日期、未知学期规则、非本科或独立校区、登录别名映射仍有适用限制。缺少专业培养方案、先修关系和学分规则时，本模块是学业看板与辅助统计，并非完整选课规划；加权绩点也不等同于学校官方认定结果。

校园密码不落库，内存会话用于已登记站点；30 天本机会话能打开离线缓存，资料库本身并未加密。自动同步只覆盖已适配来源，不代表全部校园网站或持续后台实时采集。macOS/Linux 未在本次实机验证。
