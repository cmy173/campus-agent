# 安全与权限设计

v0.2 已实现本机 Web、校园通行证（浙大统一身份认证 / CAS）登录、HttpOnly/SameSite 会话、CSRF/Origin/Host 校验、对象拥有者检查、脱敏审计和级联删除。登录不保存任何密码：账号即学号，密码只在后端内存中用于向 CAS 换取一次性票据。测试验证的是应用层边界（CAS 交互以 mock 覆盖），不是生产安全认证，也未在真实统一身份认证环境联调。

应用只监听回环地址。SQLite 数据库未静态加密，本机有文件权限的人仍可读取；解析子进程有超时、文件/解压/文字规模限制，但不是 OS 沙箱。限流部分存在内存，重启清空。未实现自动备份与保留期限；登录已接入校园统一身份认证，但尚未在真实 CAS 环境联调，也未接入教务等业务系统。下面各节是更完整的正式部署设计，不代表全部实现。

## 信任边界

用户请求是意图来源；网页、通知、文档、字幕和检索片段都是不可信数据。外部文本即使写有“忽略规则”“调用工具”也不能修改系统策略。模型输出同样需要程序校验。

正式工具网关必须使用静态注册表、参数 schema、服务端身份与最小权限；禁止模型提供任意 URL、文件路径或凭据后直接执行。检索源不允许发起网络访问或工具调用。对上传内容中的指令只可引用，不可执行。

## 身份与数据隔离

本地单用户验证后，多用户试点必须先实现应用身份认证、服务端 session、对象级 owner_id 校验，覆盖原件下载、段落检索、向量索引、任务轮询和缓存。不能信任前端传来的用户 ID。测试至少包含 A 用户不可读取、搜索或删除 B 用户资料。

未来校方授权使用经批准的认证流程。当前登录用学号 + 统一身份认证密码在后端直连 CAS 换票（借鉴 Celechron 及本地参考实现 zjuhelper 的 RSA/CAS 流程）。密码只在这一次调用的内存中存在，用完即弃：不写库、不写盘、不写日志、不进模型提示；认证失败只尝试一次，避免连续错误触发风控锁号。残余风险需明示：密码在请求期间会经过本地后端进程内存，本机有内存/文件访问权限者理论上可截获——这是相对“密码完全不经过本项目”的浏览器粘贴 Cookie 方案的取舍，换来“输入通行证即登录”的体验。若校方日后提供经批准的 OAuth/CAS 回调接入，应改用密码不经过本后端的标准重定向流程。确需保存长期 token 时用系统密钥服务或托管密钥加密，密钥与数据分离，支持撤销、轮转和最小 scope。仓库、日志、模型提示中都不能出现秘密。

## 上传与模型处理

建议初始限制单文件 20 MB、200 页，作为待测试配置；校验扩展名与实际格式，拒绝宏与可执行文件，压缩格式限制解压体积，解析运行在受限进程并设置超时。默认不 OCR，不转写音频。

原件和分段保存到隔离目录，存储 key 由服务端生成。发送模型前说明处理方、内容范围与保存策略，确认教学资料处理权限。禁止默认公开知识库或跨用户训练。

## 敏感操作

当前不实现写接口。未来确认页必须展示目标平台、具体动作、参数、影响与有效期；用户确认后生成绑定动作摘要的单次 token。执行后从平台回执或只读查询验证结果，结果不明时显示 unknown，不宣称成功，也不自动重复报名。

## 删除与审计

建议试点资料保存 30 天、脱敏审计 90 天，均是待团队决定的产品策略，不是法规要求。删除应覆盖原件、段落、嵌入、摘要、缓存及派生任务；备份按约定周期到期。日志仅保存请求标识、工具、耗时和结果码，避免全文及账号凭据。

公开部署前的门槛：隔离越权测试、上传异常测试、提示注入样本、备份恢复演练、删除验证及依赖检查全部通过。法律与学校政策判断需由项目负责人与校方核实。
