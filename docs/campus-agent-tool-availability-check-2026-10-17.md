# 每轮必查工具可用性与工具删改决策 — 2026-10-17

## 新增检查

真实 Agent 执行器现在会对**每一次模型调用**读取实际提供给模型的工具 schema 快照，并与场景中的精确 `required_tools` 对照。结果保存在每个运行 JSON 的 `tool_availability_checks`，报告页逐场景展示；批次汇总增加缺失必需工具的运行数和次数。

- `available_first_call`：首个模型调用即可见。
- `loaded_later`：初始不可见，后续动态加载后可见。
- `unavailable`：仅当该任务的所有模型调用都带完整、未截断 schema，且必需工具始终缺失时才成立。
- `not_observed`：缺少模型调用快照或快照截断；不能据此判断不可用。

工具可见性与模型选择、Harness 收到调用、执行器运行、结果回传分别记录。可见但没调用是选择/规划问题，不会冒充工具缺失。诊断器对完整快照证明缺失的工具标记已证实 A 类根因；证据不完整时标为评测观察不足。

## 工具改动决策

### 保留并修复 `web_fetch`

BUS-04 真实轨迹确认 `web_fetch` 在少数校内 hostname 上受到 `WEB_BLOCKED_URL` 地址安全策略限制；该结果不能外推成全网不可用。相同 BUS-04 批次也观察到授权浏览器成功读取公开活动页作为回退，BAS-02/BAS-03 轨迹观察到一般公网搜索/抓取使用。删除通用 `web_fetch` 会移除已观察到有用的公网能力。

保留已实施的逐 Agent-turn、精确 hostname 重复拒绝短路：它阻止相同地址策略失败的重复 provider 请求，不放宽网络安全策略，也不影响其他主机。BUS-04 n=3 显示每次都有阻断和本地短路，任务结果为 2 部分成功、1 不可验证；尚无证据证明整体任务成功率改善。因此该措施只被视为请求抑制修复，不能宣称任务能力已修好。

### 不因“零调用”删除工具

地图中若干工具当前真实调用数为 0，但零调用可能来自任务覆盖不足、动态工具未加载或模型选择行为；不是工具执行失败证据。本次不据此删除工具。对每个有精确场景的工具，后续批次会先比较首轮可见性、后续加载、调用、执行、回传和确定性结果，再决定移除或调整 schema。没有对应场景的功能先补隔离工具/Harness 测试。
