# ETA 个人基本信息适配

更新：2026-10-10。用户授权的本机协议适配；已开始隔离测试账号联调，只读取脱敏协议结构与字段可用状态。

程序在通行证登录后的自动同步中读取 ETA 个人信息，与教务个人页、课表基本信息逐字段整合。仅保存学号、姓名、学院、专业、班级和年级。每个字段保留来源、获取时间和未更新标记；缺失字段先显示其他可用数据，下次登录更新时再获取。来源失败不删除缓存，也不阻断其他教务信息。

## 登录与接口

ETA 优先验证并复用站点会话；首次连接或确认站点会话失效时，复用 CAS 主会话换票，使用学校当前公开认证配置中的 service `http://eta.zju.edu.cn/zftal-xgxt-web/teacher/xtgl/index/check.zf`；路径名不能单独代表教师权限。其注册标识是 HTTP，传输始终为 HTTPS：仅精确匹配该域名和路径的票据回调可升级为 HTTPS，失败即报告，不回退明文。CAS 主 cookie 仅发送给认证域名，ETA 保持独立站点 cookie，均只在内存。连接器固定允许 CAS、本科教务及 ETA 三个 HTTPS 域名，不接受任意 URL。

1. `getCurrentUser.zf` 验证本人；需要角色初始化时读取 `getUserRoleInfo.zf` 并仅选择返回的本人默认角色。
2. 读取 `/teacher/xshx/commonGrxx.zf?path=grxx`，发现 `userInfo` 的 extendCode。
3. 读取 `/dynamic/form/find/userInfo/<extendCode>.zf`，dataId 只使用该会话自己的标识，并按官方前端 AES-CBC/ZeroPadding 编码。
4. 若定义声明 `formDataUrl`，按官网渲染器的 GET 流程读取本人实际字段值：dataId 使用本人表单记录标识，gnczid 默认为空；GET 的 dataId/xh 按官方拦截器编码。只跟随已审核 ETA 基本信息命名空间中的只读入口，拒绝其他域名、列表、写操作、其他表单和身份参数不一致的入口。
5. 发现同一目录中的 `wdzd`（官网 Wdzd / 我的在读组件）后，按其返回的 extendCode 读取本人学籍表单；若声明实际数据入口，使用相同只读校验及本人参数。只提取学院、专业、班级和年级；姓名/学号仍保留本人身份来源。学籍来源失败保留其他来源，身份不一致拒绝整个合并。
6. 将实际值与定义对应，使用配对显示名（例如 xydm/xy）或匹配的选项标签；没有标签的学院等编码不冒充名称。`jgdm` 为已观测 userInfo 表单中的籍贯编码，不映射学院。仅保存六个基本字段，丢弃其他字段，不保存整个表单，不访问家庭、联系方式等其他表单。逐字段保存 userInfo / wdzd 的实际来源路径；识别旧错误映射时撤回同一 ETA 来源的错误学院缓存，其他来源不受影响。

相对接口均在 `https://eta.zju.edu.cn/zftal-xgxt-web` 下。未登录页面返回 200 不算认证成功；身份与已有教务学号不一致时拒绝合并。使用 cryptography 匹配当前官方请求/响应编码，兼容旧响应编码和明文 JSON；接口编码不能替代 HTTPS 或认证。诊断不保存查询参数、表单、凭据、cookie 或上游正文。数据不进入模型输入。

## 901 与访问诊断

ETA API 按官方 Axios 请求方式发送 JSON Accept，登录回调使用页面导航的 HTML Accept；均不添加 X-Requested-With。原实现把教务 AJAX 请求头扩展到 ETA 登录回调，与官方请求方式不一致，现已修正；这不代表所有 901 均由该请求头引起。本科教务查询继续保持其已验证的独立请求头，不因 ETA 故障整体改动。

遇到 901/922/429 时立即停止该来源，不自动重复换票、重试密码或更换网络出口。诊断记录固定路径、HTTP 状态、阶段及耗时，仍不记录票据、查询参数或响应正文；继续获取其他来源并保留缓存。公开入口为 https://eta.zju.edu.cn/ 。本人浏览器返回 404 与程序收到 901 是不同的观测，不能由此直接认定密码错误或接口消失。

## 响应大小与复制诊断

ETA 登录回调和跳转仅接收状态、Location 与 Cookie，关闭响应而不读取正文；页面内容大小不再阻断后续本人接口验证。HTTP 200 仍需本人信息接口验证，不能仅凭跳转完成判断成功。

ETA 数据接口上限单独调整为 8,000,000 字节，允许编码表单和选项字典；其他校园数据请求保持 2,000,000 字节上限。访问拒绝状态先于正文读取处理。超限报告固定路径、状态、limit_bytes、observed_bytes（最多读到上限加一字节）和内容类别，不记录正文、账号或查询参数。不会无限制读取。

页面展开“同步诊断”后可点击“复制诊断”，复制的仍只有上述安全元数据。浏览器不允许复制时，可选中文字手动复制。双数字学期编码（如 1|0、2|0、3|0）保留教务原值查询；不按数字组合猜季节，日期优先采用页面季学期名称。

字段不齐时生成 PROFILE_PARTIAL，诊断包含是否执行实际值请求及六个字段的 available/unavailable 状态，不包含字段值。页面区分来源失败、接口没有返回可识别字段和未读取来源。诊断增加运行连接器版本 connector_revision 与同步记录版本 sync_revision；旧记录不会因查看被改写，新运行版本与缓存版本不同会提示重新登录更新。`/api/health` 的 campus_connector_revision 可确认重启后加载的版本。当前版本为 `2026-10-12.custom-status`，ETA 协议移至 `connectors/profile_protocol.py`，统一基本信息能力见 [连接器指南](connectors.md)。

官网还支持竖线组合 fieldCode（例如 bmdm|zydm|nj|bjdm）。连接器按定义顺序匹配完整 defaultLabel 路径、实际值中的配对显示名或 options 的对应子路径，拆出学院、专业、年级和班级；拒绝错位标签，不把未识别的单位/专业/班级代码当名称。支持表单内 data/formData/values/curDatas 值。因此 data_request=false 也可能是正常内联表单，不能单凭它认定漏请求。部分字段诊断新增 schema_shape，只含组/字段数量、六个标准字段的映射及值/标签类型，不含源字段名或内容。

08:53:29 的新版诊断确认 xsxg 内联表单只取得姓名/学号；尚未取得其真实表单结构，级联解析补充不能据此声称已经解决该账号。学期后缀长度为一且类别 other，可能是中文或损坏字符，不能确定。教务 HTML 现在识别响应头/meta 中的 UTF-8、GBK/GB2312/GB18030，缺少或错误声明时采用严格解码候选，不再用 U+FFFD 替换字符发起查询。原样接受页面返回的单个汉字后缀，不由它猜季节；聚合/占位项过滤继续生效。未知后缀诊断区分 cjk、replacement 与 other，并记录所用编码。

教务 JSON 的 error=0/"0"/false/"false" 不再误判为失败。真正拒绝时保留固定接口路径、已验证的学年/学期参数、成功标志、错误类型及 kbList/items/xsxx 类型；不会保存错误原文。已知验证码/权限提示归为相应类别，保留其他站点会话。用户给出的 UPSTREAM_ERROR 无正文信息，尚不能证明其根因是 error="0" 或验证码。

## 空表单与 HTTP 阶段（2026-10-10）

09:57:23 的真实诊断不再有学期编码警告，但 xsxg 响应没有可识别 groupFields。仅能确认未识别出定义，不能确认学校完全没有这些字段。连接器现在只在返回的 userInfo 入口不可解析时，额外尝试官网代码中已知的 userInfo/default，只读、同一本人 dataId、一次；拒绝外层或内层身份不一致。支持 form/formData/formDatas/definition/data 的字典或受限 JSON 文本包装，读取同行的本人实际值；不遍历其他个人模块。仍失败则报告 PROFILE_FORM_UNAVAILABLE，姓名/学号只归属已验证 getCurrentUser 来源，保留缓存；不再把它描述为“已读取基本信息，仅部分字段缺失”。诊断的 form_attempts 只含固定路径与脱敏结构，不含数据或参数。

此前 HTTP 非 200 在 page_request 中直接报错，遗漏诊断；现先处理状态，再解码正文，保留状态、路径、已验证查询参数与内容类别。非 JSON 也带安全阶段诊断。连续三次 5xx 暂停本轮自动续传，保留未查询学期，允许用户稍后继续；单个学期错误仍可继续其他查询。这不是对用户实际错误状态的猜测，真实状态需新同步记录确认。
