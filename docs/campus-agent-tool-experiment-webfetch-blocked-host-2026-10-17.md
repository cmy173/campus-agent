# `WEB_BLOCKED_URL` 同主机重复请求抑制实验 — 2026-10-17

## 证据与假设

BUS-04 既有两个真实模型批次都观察到 `WEB_BLOCKED_URL`。按已保存、脱敏后的 Harness 轨迹统计，对照批次 `20261017-084822-adb5957b` 共 10 次、处理批次 `20261017-085326-b3e75622` 共 7 次。失败集中于少数主机，部分主机在同一 Agent 任务内重复 fetch。工具已有恢复提示要求不要更换相似域名反复重试，但真实轨迹显示提示没有阻止模型重复调用。

可证伪假设：某精确 hostname 在一次 Agent 生命周期内返回 `WEB_BLOCKED_URL` 后，同一生命周期的后续 fetch 不可能通过换路径修复 DNS 地址策略拒绝；在 Harness 边界短路该主机的重复请求，会减少外部请求和等待，同时保留对其他 hostname 及新 Agent 生命周期的正常访问。

当前测试主机的系统 DNS 对 `www.zju.edu.cn`、`www.intl.zju.edu.cn` 和 `px.zju.edu.cn` 返回 private 地址分类。这与地址安全门拒绝相符，但不能证明 provider 侧 WebFetch 使用同一 DNS 解析器；未改 DNS、网络策略或 allowlist，也未尝试 IP 直连。

## 改动

仅改变 Agent runtime 的 `web_fetch` 错误恢复策略：每个 Agent 对象在内存中持有本轮被 `WEB_BLOCKED_URL` 拒绝的**精确 hostname** 集合。相同主机后续调用立即返回同一错误码和恢复说明，不再触发底层 provider；不同主机不受影响。状态使用 `WeakMap`，只存主机名，不记录 URL 路径、查询、页面内容或用户数据，也不会跨 Agent 对象持久化。

实现：`apps/agent-runtime/web-recovery.mjs`。真实 BUS-04 批次使用源码指纹 `c5f87d34e0d62aabb793be09035f8cc23921a263013ffbc25d66f72dd47fa569`。

## 决策与下一步

保留这项短路：它只减少已经被安全策略明确拒绝的重复外部请求，不放宽地址、认证或校园副作用边界。BUS-04 仍未确认成功，未解决的核心阻碍是官方来源的地址策略拒绝及部分来源无法核验。下一轮应在新建隔离 API 和相同模型条件下做交错、至少 3 次的 BUS-04 复测；还要确认 `agent/created` 的生命周期与每个用户回合一致，避免跨回合遗留阻断。不要把本次单次验证宣称为任务成功率提升。
