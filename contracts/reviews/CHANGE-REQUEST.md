# 契约变更申请（Change Request）模板

> 用法：复制本文件为 `YYYY-MM-DD-CR<NNN>-<简述>.md` 填写；编号 `CR<NNN>` 全局递增，由 B 分配。
>
> 规则（v0.1 冻结批次起生效）：
> - 冻结后的契约**仅接受兼容新增**（新端点、新可选字段、新枚举值需评估影响）；**breaking 变更一律推 v0.2**。
> - 状态流转：`draft`（提出）→ `in-sync`（相关智能体同步意见）→ `accepted`（B 裁决）→ `merged`（补录契约并记录 CHANGELOG）/ `rejected`。
> - 涉及多方的申请应**一次性汇总同步**，避免多次小改。
> - 凭据安全红线（登录/会话/令牌不落库、不下发网页、不进日志）不受任何变更申请豁免。

## 基本信息

- **编号**：CR\<NNN\>
- **日期**：YYYY-MM-DD
- **提出人**：智能体 \<A/B/C/D\>（或用户/协调者）
- **状态**：draft / in-sync / accepted / rejected / merged
- **关联**：任务编号（如 A12/B12）、决策记录（如 `docs/coord/02-M1阶段计划与智能体任务书.md` §5.1）

## 变更类型

- [ ] 兼容新增（新端点 / 新可选字段 / 新枚举值——评估后并入当前版本）
- [ ] 补充说明（不改结构，仅澄清语义/文案）
- [ ] breaking（→ v0.2；必须说明为何不能兼容、影响哪些既有实现）
