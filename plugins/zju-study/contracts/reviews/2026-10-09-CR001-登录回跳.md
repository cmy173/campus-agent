## 背景与动机

用户决策（2026-10-09）：平台连接改为**跳转式登录**——C 网页端「连接平台」→ 跳转到平台权威通行证页面 → **用户自行输入凭据**（凭据只存在于官方页面与用户浏览器）→ 平台回跳我方回调地址 → 回跳 C 网页端展示状态。原 v0.1 契约前提「首次建立连接不在 API 内」由此改变，需新增「开始授权 + 平台回调」两个端点（兼容新增）。

硬要求（§5.1，不随本申请谈判）：凭据永不进入我方系统；state/配对令牌一次性且带有效期；回跳地址白名单、拒绝任意 `redirect_uri`；会话与令牌不出浏览器/本机、不进 API 响应/网页存储/日志；失败与过期返回 `auth_required` + `recovery_action.entry_url`，`AUTH_EXPIRED.retryable=false` 不循环重试。

## 提案内容

### 1. 开始授权

`POST /api/v1/connections/authorize`（支持 `Idempotency-Key`：同键同体重放返回同一 state 响应）

请求：

```json
{ "platform": "xzzd", "redirect_target": "http://127.0.0.1:5173/connections" }
```

- `platform`：`xzzd` | `zykt`（沿用连接平台枚举）。
- `redirect_target`：回跳 C 的落地地址，**必须命中服务端白名单**；未命中 → `400 VALIDATION_FAILED`（错误消息不回显白名单全集）。

响应 `201`：

```json
{
  "login_session": {
    "state": "<43 字符 urlsafe>",
    "platform": "xzzd",
    "entry_url": "https://<平台权威登录入口，已携带平台侧回跳参数>",
    "expires_at": "2026-10-09T15:00:00Z"
  }
}
```

- `state`：密码学随机（32 字节），**一次性**（回调消费即失效）、`expires_at` 到期失效（默认 600s）；同平台允许多个在途会话。
- `entry_url`：平台权威登录页（含平台要求的回跳/登记参数）；具体形态由 A12 结论确定，A12 前为服务端配置占位并**不得宣称真实可用**。

### 2. 平台回调（浏览器流，非 JSON 消费端点）

`GET /api/v1/connections/callback?state=<...>&<平台自定义参数>`

服务端处理顺序：

1. **state 校验**：查 `login_states` 并**原子消费**（`UPDATE ... WHERE state=? AND consumed_at IS NULL AND expires_at>now`，rowcount=0 即重放/过期/不存在）→ 失败一律 `409 AUTH_EXPIRED`（`retryable=false`，`details.action={type:"user_login", entry_url:<服务端默认入口>}`；重放与过期不可区分对外）。
2. **绑定连接**：按 `platform` upsert `connections` 行：新建或复用既有行，更新 `updated_at`；`status` 与 `capabilities` 的落值见 DECISION-2；`recovery_action` 清空或按失败原因写入。
3. **回跳 C**：`302` 到该 state 记录的 `redirect_target`，附 `login=ok&connection=<conn_id>`；失败附 `login=error&reason=<AUTH_EXPIRED|SERVER_ERROR>`。**重定向 URL 不携带任何平台参数/令牌/state 值**。
4. **平台自定义参数**（ticket/code 等，如有）：仅按 A12 约定的通道**透传**给会话归属方（B 或 A 本地服务）用于一次性交换/校验；B 侧**不落库、不进日志（日志剔除查询参数）、不回显**。若 A12 结论为不可回跳或无参数回跳，则第 4 步按结论删减。

### 3. 安全红线（实现约束，任何结论下不削减）

1. 无凭据收集/代填/落库/日志/响应；2. state 一次性 + TTL + 原子消费防重放；3. 白名单，不接受任意 `redirect_uri`；4. 回跳不携带平台参数；5. 服务端日志统一剔除 URL 查询参数（B 侧 `app/log_redact.py` 已实现，覆盖 uvicorn access 日志）；6. `AUTH_EXPIRED.retryable=false`，`recovery_action.entry_url` 指向 C 的重连入口，**不循环重试**；7. 能力如实三态，未实测保持 `unknown` 并附证据，**禁止把模拟写成真实成功**。

## 待决问题

- **DECISION-1（A12 裁定）**：两平台通行证是否支持回跳到约定本地地址；登录入口 URL、回跳参数（CAS ticket / OAuth2 code / 无参）与会话归属（B API 进程 vs A 本地服务）。建议默认：先按「本地地址回跳 + 参数透传给 A 本地通道」实现骨架；若不可回跳，降级为「本地服务持有会话 + 网页端只读展示」（§5.1 降级方案），本 CR 的端点形态随结论调整。
- **DECISION-2（A12 与 B 共同裁定）**：回调成功后的 `connection.status` 与 `capabilities`。建议默认：**回跳完成 ≠ 连接可用**——仅当回跳携带可验证凭据（或本地服务确认会话可用）时置 `ok`；否则保持 `auth_required` 并在 `last_error` 载明「已回跳、会话待确认」；`capabilities` 全量 `unknown` + evidence「待 A5b 实测」。避免假 `ok`。
- **DECISION-3（A12 提供）**：`entry_url` 的平台入口模板与所需登记/申请步骤（A12 可行性结论的第①项）。

## 迁移方式

- **兼容性**：纯新增端点与对象，无既有字段变更；C 增加按钮流；未接入前既有页面行为不变。
- **版本处置**：并入 **v0.1 冻结批次**——与 A12 同步结论后**一次性补录**（openapi + 新 schema + CHANGELOG），避免多次小改；breaking 不适用。
- **上线窗口**：B 侧骨架可先行为 C 提供联调（以本 CR 为临时口径）；契约正式补录后以补录版为准。
- **回滚方式**：删除两端点与 `login_states` 表（无对外数据依赖，连接数据保留）。
