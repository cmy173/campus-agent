## 背景与动机

用户新轮次要求实现「复习卷」功能：用户自行填写 API 地址/模型/密钥并测试连通；选择课件正文、作业正文及附件为材料；备注完整原文随材料发模型；后台出卷作业（进度/取消/有限重试/幂等）；试卷、答案解析、来源与历史版本持久化与导出。跨模块需要先冻结共享结构，A（题库边界）、C（网页流程）、D（出卷引擎）才能并行开发、B 才能统一发起模型请求。

本轮为**兼容新增**（冻结后仅按此规则并入 v0.1），无 breaking。

## 提案内容

### 1. 新增 Schema（`schemas/`，均 JSON Schema 2020-12）

| Schema | 用途 |
| --- | --- |
| `provider-config.schema.json` | AI 服务配置（仅 `openai_chat_completions` 协议）；**密钥永不回传**，仅 `has_api_key`；含 `TestResult`（`ok/checked_at/latency_ms/http_status/error`） |
| `review-request.schema.json` | 出卷请求：`course_id`、`mode`（ai/bank/hybrid）、`provider_config_id`、`title`、`materials{resources[{resource_id,version,chunk_ids}], assignments[{assignment_id,include_attachments}]}`、`notes`（maxLength 20000）、`constraints{question_types[{type,count,points_each}], difficulty, total_points, duration_minutes, answer_display}` |
| `material-snapshot.schema.json` | 材料快照（受理时冻结）：`items[{kind resource_text/assignment_text/attachment_text, …, chunk_ids, locators, chars, text}]`、`missing[{reason: not_parsed/not_accessible/…}]`、`notes{text, sha256, chars}`、`fingerprint`（公式见下）、`engine_version` |
| `review-material.schema.json` | 课程复习材料清单条目（提取自 openapi 组件，供 `GET /courses/{id}/review-materials` 与 openapi `$ref` 共用一个定义） |
| `review-preflight.schema.json` | 预检结果：将发送的正文与备注预览、缺失清单、provider 摘要（含 `host`）、限制、`bank{mode, usable, …}`、fingerprint 预览 |
| `questionbank-capabilities.schema.json` | 题库来源能力三态（`configured/searchable/fetchable/answer_available/formula_support`），未配置如实 null/false |
| `bank-search-request.schema.json` | B → A 检索请求（`course_title`、`query_terms`、`knowledge_points`、`question_type`、`difficulty`、`language`、`count`、`domains`） |
| `bank-candidate.schema.json` | A → B 候选题（`origin_type original/adapted`、`source{url,site_name,original_id,locator}`、`answer`/`explanation` 可为 null——**缺答案不伪造**） |
| `paper-blueprint.schema.json` | 出卷蓝图：`sections[{knowledge_points[{name,weight,evidence{kind courseware/homework/note}}], question_slots[{slot_id,type,count,points_each,difficulty,source_plan}]}]`、`type_quotas`、`difficulty_quota`、`gaps` |
| `review-question.schema.json` | 试卷题目：`answer`/`explanation` 必填非空；`origin{kind ai/bank/adapted_bank, candidate_id}`；`source_refs` minItems 1；`validation{status valid/repaired/low_confidence/incomplete}` |
| `review-paper.schema.json` | 试卷（含 `snapshot`、`blueprint`、`questions`、`warnings`、`summary`、`revision`、`revision_reason`、`based_on_revision`、provider 快照） |
| `review-paper-revision.schema.json` | 修订历史索引条目（`paper_id/revision/revision_reason/based_on_revision/fingerprint/summary`） |

共享枚举（`common.schema.json` 新增）：`review_mode`（ai/bank/hybrid）、`question_type`（single_choice/multiple_choice/true_false/fill_blank/calculation/short_answer/proof）、`difficulty`（easy/medium/hard）。

`job.schema.json`：`type` 枚举新增 `review_generate`；新增可选 `phase`（null 或 `materials/blueprint/bank_search/generation/validation/saving`，进度细节；旧消费者不受影响）。

### 3. 关键冻结语义

- **fingerprint 公式**：sha256 over `json.dumps({course_id, mode, engine_version, notes_sha256, constraints, materials:[{kind,id,version,content_hash,chunk_ids,chars}]}, sort_keys=True, separators=(',',':'), ensure_ascii=False).encode('utf-8')`，格式 `sha256:<hex>`。预检/试卷/修订历史中一致即同一输入。（样例基准值 `sha256:558ccbada7569a59bcd34659913c800ceb5c695af4b81d91f78ffb892cf2d811`）
- **备注原文**：逐字节进快照与模型请求（`sha256`+`chars` 留痕）；超 20000 字符 400 `VALIDATION_FAILED`，**不静默截断**；多行 `\n` 原样保留。
- **正文拼接口径**：资源正文 = 所选片段文本按 `ordinal` 以 `"\n"` 连接（`chars = len(拼接文本)`）。
- **URL 规范化**：去首尾空白与末尾斜杠；仅 http/https、无查询串/片段/用户信息；http 仅限本机/内网地址；路径为空补 `/v1`，其余路径原样（不重复拼 `/v1`）；拒绝 `/chat/completions` 后缀与 `v1/v1`；实际请求 = `base_url + "/chat/completions"`；不跟随重定向；响应大小有上限。
- **重试与取消**：模型调用 429/超时/5xx 有界重试（≤2 次）；401 永不重试；修复轮 ≤1 次；作业可取消（`GET /jobs/{id}` 轮询 + `POST /jobs/{id}/cancel`）。
- **revision 模型**：受理不改写历史；保存时分配 `latest_revision+1`；`based_on_revision` 留痕；重做不覆盖旧版。
- **模型请求仅由 B 发起**；只带用户选定资料原文、检索词与备注，不带学校 cookie/临时链接/密钥。密钥仅存本地（Windows DPAPI，`STUDY_SECRETS_DIR`），不落库、不进响应/日志/导出。
- **模式如实三态**：bank/hybrid 无可用题库来源时 400 `BANK_NOT_CONFIGURED`（不假装搜到题、不静默切 ai）；A/D 模块未接入时 502 `DEPENDENCY_UNAVAILABLE`。

### 5. 模块接缝（冻结接口签名）

| 方向 | 模块（默认，可环境变量覆盖） | 接口 |

## 迁移方式

- **兼容性**：全部为新增（新路径、新 schema、新可选字段）；既有 40 路径、既有客户端零改动；`job.schema.json` 为放宽式修改（`type` 扩枚举、新增可选 `phase`），旧消费者解析不受影响。
- **版本处置**：并入 v0.1（冻结批次「兼容新增」规则），CHANGELOG 记 CR008。
- **数据**：增量迁移（新表 + `jobs.phase` 可空列），回滚 = 降一档迁移；`var/personal.db` 个人数据不受影响（迁移仅新表/新列）。
- **上线顺序**：契约先行（本 CR）→ B 后端（模型 #44–#49）→ A 题库 / D 引擎接入 → C 网页 → 四模块联调。A/D 未接入期间端点如实 502/400，C 可按样例开发与联调。
