日期：2026-10-10｜执行：智能体 C｜范围：`apps/web/`（agent/c worktree）

## 0. 结论摘要

- 任务书点名的 4 个组件（ChunksDrawer / BuildTasksDrawer / JumpLoginModal / 完成反馈弹窗）＋挂接来源弹窗：**打开时焦点移入容器、Esc 关闭、关闭按钮可读名称**均在真实浏览器实测通过（§2）。
- 表单错误可读：错误文案可见 + 控件 `aria-invalid="true"` + `aria-describedby` 指向错误节点（实测，§3）。
- 全站复检计数：按钮/链接/表单控件 **0 个无名称**（唯一例外是 antd Tabs 内建、无溢出时隐藏的 `.ant-tabs-nav-more`，非用户控件，§5）。
- 本轮补齐 12 处 `aria-label`（可用时间 7、任务生成范围 1、同步筛选 2、导入选择 1、挂接平台 1，§6）；移除 2 处 `forceRender`（其破坏打开时焦点移入，§3.3）。
- **限制**：关闭时“焦点归还”与 Tab 陷阱为**源码级核对**——rc-motion 动画在隐藏页不结束，归还动作是动画后触发的，无法在本环境观测（§4、§8）。

## 1. 环境与方法

- 浏览器：QoderCN 0.4.3（Chromium 150.0.7871.114 / Electron 43.1.1），**隐藏标签页**；被测服务 `http://localhost:5173`（真实模式）。方法（同源离屏 iframe + 收束等待）与 C14 记录一致。
- 焦点观测：`contentDocument.activeElement` 及其 `className` / `aria-label` / 容器归属（`closest('.ant-drawer/.ant-modal')`）。
- Esc 触发：向 iframe `contentWindow` 派发合成 `KeyboardEvent('keydown', { key: 'Escape', bubbles: true })`。rc-drawer/rc-dialog 监听 window 的 keydown（源码：`@rc-component/drawer/es/Drawer.js` L108-116 `onEsc`；`@rc-component/portal/es/useEscKeyDown.js`），合成事件走同一链路。
- 名称口径：按钮/字段“无名称” = 无 innerText / `aria-label` / `aria-labelledby` / `label[for]` / 包裹 label / `title` / `img[alt]`；“弱名称” = 仅靠 placeholder。
- 关闭态观测：drawer 看 `ant-drawer-open` 类与节点是否卸载；modal 看是否出现离场类 `*-leave`（冻结环境下反场动画停留，可作“已触发关闭”的证据）。

## 3. 表单错误可读性

### 3.1 挂接来源弹窗（空提交，最终代码复证）

- 错误 2 条（`.ant-form-item-explain-error`）：`请选择平台`、`请填写平台课程标识`。
- 平台下拉的内层控件 `input[role="combobox"]`：`aria-invalid="true"`、`aria-describedby="platform_help"`；`#platform_help` 节点文本 =「请选择平台」（指向错误文案本身；该 id 由 antd Form.Item 自动接线）。
- 控件本身有可读名称：`aria-label="选择平台"`（本轮补，§6）。

### 3.2 可用时间表单

- 逐字段校验与提示为 M1 既有（`src/lib/validation.ts`）；本轮为 TimePicker / InputNumber / DatePicker / 备注输入补 `aria-label`（§6），使每个控件有稳定可读名称，错误文案由 antd Form.Item 的 `role=alert` 说明节点呈现。

### 3.3 移除 `forceRender`（2 处）

- TodayPage 反馈弹窗、AttachSourceRef 挂接弹窗：`forceRender` 会让内容在关闭态提前挂载，**破坏 rc-dialog 打开时的焦点移入**（实测：带 forceRender 时打开后 `activeElement` 停留在 body）。移除后两处打开焦点均到 `.ant-modal-close`（§2）。
- 关联修复：反馈弹窗 `destroyOnHidden` 重挂载会让表单残留上一任务的输入 → 打开按钮的 onClick 中 `resetFields()`＋`setFieldsValue(预填)`（TodayPage；vitest 反馈流程用例持续通过）。

## 4. 焦点归还与陷阱（源码级核对 + 环境限制）

- rc-dialog：`@rc-component/dialog/es/Dialog/Content/Panel.js` L41 `useLockFocus(visible && isFixedPos && focusTrap !== false, …)`——打开时锁焦并把焦点移入容器；**“归还焦点到触发元素”在动画结束后执行**。
- rc-drawer：`@rc-component/drawer/es/hooks/useFocusable.js` L4-7 `mergedFocusTrap = focusTrap ?? mask !== false`（默认开启）、`useLockFocus(open && mergedFocusTrap, …)`。
- 环境限制：隐藏页 rAF 冻结 → rc-motion 不结束 → 归还动作（动画后触发）**无法观测**；实测关闭后 `activeElement` 为 body / 抽屉根，属环境伪影，不作为缺陷记录。
- Tab 陷阱（不逃逸）：由上述 `useLockFocus` 焦点锁实现，源码级核对属实；**本环境无法驱动真实 Tab 焦点环，未做行为实测**（§8）。

## 8. 已知限制（口径）

- 关闭后焦点归还、Tab 陷阱行为：隐藏页环境不可观测（motion 门控），仅源码级核对 + 待前台真机复核（M3 前的复核清单项）。
- Esc 为合成键盘事件（与真实按键走同一 window keydown 链路）；原生按键端到端复核同样建议留至前台环境。
- 未做：屏幕阅读器实测（如 NVDA/讲述人）、颜色对比度审计（M3 范畴）。
- “0 个无名称”为按 §1 口径的自动计数，不覆盖语义质量（名称是否准确描述操作）之外的人工判读——已抽查主要操作名称与按钮文案一致。
