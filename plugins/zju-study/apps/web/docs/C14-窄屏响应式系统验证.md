# C14 窄屏响应式系统验证与修复

日期：2026-10-10（M2 起步轮）｜执行：智能体 C｜范围：`apps/web/`（agent/c worktree）

## 0. 结论摘要

- 走查 7 条路由 × 3 档宽度（375 / 768 / 1280）= 21 格，**修复前发现 1 类窄屏阻断缺陷**：992px 以下侧栏仍在文档流内，展开时把内容区挤压到 160px 并产生 17px 横向溢出（实测）。
- 修复（`index.css` + `AppLayout.tsx`）：< 992px 时侧栏改为固定定位浮层（`position: fixed; top: 64px`）+ 遮罩层，点遮罩收起；桌面行为不变。
- 修复后三档复测：**21/21 格横向溢出为 0**，侧栏 375/768 收起（浮层恒定位）、1280 展开（文档流内 200px），内容区宽度 = 视口宽（含滚动条扣除）；展开态为浮层不挤压内容（收束态模拟验证，见 §4）。
- 首次引导（/onboarding）与课程详情（/courses/:id）未发现额外窄屏问题；抽屉/弹窗在窄屏下由 antd 自动收窄到视口宽（见 §5 几何实测）。

## 1. 环境与方法

- 浏览器：Qoder 内置浏览器 QoderCN 0.4.3（Chromium 150.0.7871.114 / Electron 43.1.1，Windows x64），**隐藏标签页**（非前台窗口）。
- 被测服务：worktree 内 `npx vite --port 5173`（真实模式，`/api` 代理至 127.0.0.1:8000）；`http://localhost:5173`。
- 方法（可复现）：
  1. 在浏览器页内创建**同源离屏 iframe**（`position: fixed; left: -99999px; width: <档位>px; height: 900px`），逐个加载路由；iframe 视口即被测宽度。
  2. 等待“收束”：`contentDocument` 无 `.ant-skeleton / .ant-spin-spinning` 且 `body` 文本 > 40 字符（超时 30s）。
  3. 度量：`documentElement.scrollWidth - clientWidth`（横向溢出 px）、`clientWidth`、内容区宽度、`.ant-layout-sider` 计算样式（`position`/宽度）、`.app-sider-mask` 是否存在、`.ant-card` 数量（内容确实渲染）。
  4. 等待原语：环境存在 Chrome 后台计时器节流（长时间隐藏后 `setTimeout` 被拉伸到约 1 次/分钟），**一切等待用 MessageChannel 让出循环实现，不依赖定时器**；rAF 在隐藏页冻结，动画类断言不可用（见 §6 限制）。
- 缺陷复现口径（修复前）：“展开侧栏后内容区被挤压”在冻结环境属静态布局结果（不依赖动画），可直接度量；侧栏收起（默认态）三档当时即无溢出。

## 2. 缺陷与修复（C14 主项）

### 2.1 缺陷事实（修复前实测）

- `__c14b/__c14c` 走查（21 格）+ `run3` 专项探针，375px 档展开侧栏后：
  - `sider-open-375-motionless`：siderW 200 / contentL 200 / **contentW 160** / **overflowX 17** —— 内容区只剩 160px、页面横向溢出 17px；
  - 收起态 `siderW 1`（antd `collapsedWidth={0}`），无溢出；1280 档始终正常。
- 根因：antd `Layout.Sider` 默认在文档流内，`breakpoint="lg"` 只控制折叠不改变定位；992px 以下展开即挤压。

### 2.2 修复内容

- `src/index.css`（L20-39）：新增 `@media (max-width: 991.98px)`：
  - `.app-sider { position: fixed; top: 64px; bottom: 0; left: 0; z-index: 1000; box-shadow … }`
  - `.app-sider-mask { position: fixed; inset: 64px 0 0 0; z-index: 999; background: rgba(0,0,0,.45) }`
- `src/components/AppLayout.tsx`：
  - `<Layout.Sider className="app-sider" …>`（L44）
  - 新增遮罩：`{isNarrow && !collapsed && <div className="app-sider-mask" aria-hidden="true" onClick={() => setCollapsed(true)} />}`（L58-60）
  - 汉堡按钮保留 `aria-label="切换导航"`（L72-77）
- 语义：桌面（≥992px）行为与样式不变；窄屏展开=浮层+遮罩，点遮罩或点菜单项收起（原 `onClick` 逻辑 L52-54 不变）。

## 4. 展开态浮层行为（收束态模拟）

冻结环境下侧栏“展开”动画（rc-motion）不前进，直接断言展开后几何不可靠；采用**收束态模拟**：加载 375 档 /today，点汉堡，然后给侧栏内联写入收束后的样式（`position: fixed; left: 0; top: 64px; width: 200px`）再取值：

- `hamburger.found = true`（`aria-label="切换导航"` 可命中）；点后遮罩出现（`mask=true`，sider 类含 `ant-layout-sider-below app-sider`）。
- 模拟收束后：`siderRect = { l: 0, w: 200, top: 64 }`；菜单项“今日”宽 127（文字未被压缩）；`clientW 360 / overflowX 0`（浮层不挤压内容）；在侧栏区域做 `elementFromPoint` 命中 `A.`（**hitInSider=true**，浮层在最上层可点击）；菜单六项文本齐全：今日 / 课程与资源 / 学习计划 / 同步中心 / 设置 / 使用引导。
- 点击“课程与资源”：iframe 路径变为 `/courses`（navOk=true），点击后自动收起逻辑与代码一致。

注：以上为“收束态模拟”，非动画断言；动画完成态由后续真实浏览器人工可复核（§6）。

## 5. 抽屉与弹窗在窄屏的几何（既有行为复核）
