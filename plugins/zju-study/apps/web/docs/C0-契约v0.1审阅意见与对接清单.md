## 4. 待 B（或 B/D）答复的语义问题

1. **预览差异来源（直接影响计划页核心交互）**：`PlanBlock` 冻结无 `change`。「新增/移动/保留」标签的预期来源是客户端对比「候选 vs `GET /plans/current`」吗？若按 `task_id` 关联对比（同任务起点相同=保留、不同=移动、新任务=新增），请确认：候选与生效计划中同一任务的块是否可稳定按 `task_id` 匹配；「生效计划中有、候选未安排」的块（移除）是否也需展示。
2. **反馈闭环**：`outcome=completed` 是否由 B 同步把 `task.status` 置 `completed`（UI 以便直接采用响应中的 `task`）？`difficulty/actual_minutes` 是否需要在任务或页面上回显「最近反馈」——有无读取端点；若无，C 仅按 `FeedbackResponse` 即时更新，不做历史展示。
3. **任务→来源对象跳转**：「去学习/去查看」按 `source_refs`（platform+external_id）与已加载的作业/回放/资料列表匹配是否可行？还是 B 计划在任务上直接给出关联对象 id 或 `canonical_url`？
4. **defer（延后）语义**：冻结 `FeedbackRequest` 无 defer，`LearningTask.status` 亦无 deferred。今日页「延后」与缺口「顺延一天」如何表达？选项：(a) C 改为 `PATCH /tasks/{id}` 调整 `due_at`；(b) 复用 `outcome=skipped` + 服务端约定；(c) v0.1 移除该按钮。请 B/D 裁决。
5. **`Resource.chunk_count` 与 `duplicate_of`**：资料列表的「查看片段（N）」徽标与「与资料 X 内容一致」去重提示需要这两个字段（B 派生，成本低）。若不入 v0.1，C 将去掉徽标、去重提示改为通用文案。
6. **回放→转写片段关联**：`transcript_resource_id` 未入冻结。v0.1 若字幕能力未实测（A 置 unknown），C 将回放页字幕区显示「待接入」；后续关联方式请 B 与 D/A 明确。
7. **Job 按钮的显示规则**：`allowed_actions` 移除后，「取消」（queued/running 可取消，协作式需文案）与「重试」（failed/partial_failed 可重试）是否可由 `status` 直接派生？`progress=null` 的不确定进度、`partial_failed` 的 `errors[]` 明细展示 C 按冻结结构实现。
