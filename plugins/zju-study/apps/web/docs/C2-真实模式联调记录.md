## 4. 错误信封核对明细（验收 ③）

全部经 `client.ts` → `http.ts` 解包为 `ApiError {status, code, retryable, details, requestId}`：

| 场景 | HTTP | code | retryable | 备注 |
|---|---|---|---|---|
| 读不存在的课程 | 404 | `NOT_FOUND` | false | `details={kind,id}`；`request_id` 格式 `req_*` 一致 |
| 非法任务体（空标题/负时长） | 400 | `VALIDATION_FAILED` | false | details 含 pydantic `errors[].loc/msg`（示例形状为 `fields`，见 §5 注） |
| 预览后输入变化再应用 | 409 | `PLAN_STALE` | false | 语义正确：拒绝应用并提示重新预览；`current_input_revision` 可取 |
| `auth_required` 连接执行同步 | 409 | `AUTH_EXPIRED` | false | `details.action.entry_url=https://classroom.zju.edu.cn/`，可直接驱动 C12 重登录入口；**不循环重试** |

> 注：`VALIDATION_FAILED.details` 实际为 `{errors:[…]}`（pydantic 原生），契约示例为 `{fields:[{field,reason}]}`；同属 §3.2 类命名差异，未单列偏差（详情结构可用且信息更全），建议 B 在 B14/CR003 批一并裁定。

## 5. mock 与 real 一致性（验收 ④）
