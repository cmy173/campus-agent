## 2. 校准输入审计（为什么无法校准）

`minutes_per_unit` 生效条件：`extent_value` 与 `extent_unit` 同时非空且单位可识别（`taskgen._estimate_resource_minutes`）。
样例实测：**28/28 资源两项均 null**（PROVENANCE §2 明示"篇幅只能来自解析（D2），不能来自元数据"）。
→ 页/张估算路径在真实摄入数据上**完全休眠**；28 个阅读任务全部静默兜底 `reading=60`（`tests/test_d10_real_samples.py::test_extent_dormant_reading_tasks_fall_back_without_warning`）。

兜底时长校准依赖反馈闭环：D6 `calibrate_estimates` 需实际耗时（`FeedbackRecord`，每类 ≥3 条、单步 ≤0.15）。
样例不含任何耗时观测（作业无说明、无附件、无提交时长），本轮校准流程（D7 §5）第 1–3 步均无输入。

## 3. 实际观察清单（全部已钉为断言）

### 3.1 规模与确定性

- 28 资源（crs_5a1b01 21 / crs_5a1b02 7）+ 62 作业（8 / 54）。
- `build_tasks_json` 产出 **90 任务 = 28 reading + 62 assignment**，ID 唯一；同输入连续两次调用 JSON 逐字节一致（确定性保持）。
- **warnings == []**：真实样例不触发任何生成告警（无重复内容、无版本族、无字符单位、无缺时长回放）——告警通道在真实数据上无误报。

### 3.2 已知偏差：5/28 文件超默认解析护栏（观察 → 需产品裁决）

- 默认 `ParseLimits.max_file_bytes` = 30,000,000；超限 5 件，超出量级远大于阈值：
  - 4 个 mp4（kind=other，`preview_only` 不可下载）：411 MB / 472 MB / 495 MB / 867 MB（`res_r10a001/002/003/006`）；
  - 1 个 PDF（full 许可）：42.9 MB（`res_r10a019`）。
- 前 4 件同时受"不可下载"限制，实际不入解析链；**res_r10a019 是唯一"可下载但超限"**：按当前默认护栏 D2 会拒绝（`FILE_TOO_LARGE`）→ 该资料将永远无法生成基于解析的估算。属产品口径问题，非缺陷；建议 B/A 裁决（提高上限 / 流式解析 / 显示"暂不支持"均可）。
- 参考：非超限文件 15,743 B – 23.3 MB，分布连续——30 MB 护栏对"文档类"余量充足，仅命中大 PDF/视频。

### 3.3 映射观察（如实记录，非缺陷判定）

- 4 个 mp4 资源 kind=`other` → 当前映射生成 **reading 任务**（资源类别非文件格式；D7 §3 的兜底策略使然）。学习形态上它们更接近"观看"，是否单独映射留作产品决策。
- `mime_type` 恒 null（平台元数据无 MIME，仅粗分类 document/video）→ D7 §2.1 对齐的 MIME 字段在摄入侧同样休眠，实际值只能来自 D2 解析。
- `content_hash` 恒 null → 跨文件重复检测（DUPLICATE_CONTENT）在**摄入时**不可触发；哈希由 B/D2 后续生成，去重仅在生成哈希后有效。
- 3 条已提交作业（`asg_r10b20/27/28`）**仍生成任务**——生成不按 `submission_status` 过滤（是否过滤留作产品决策）。

### 3.4 截止时间（与 D7 假设对照：一致）

- 62/62 `due_precision=datetime`，0 条 null；格式恒为 ISO 8601 UTC `Z` + 毫秒（如 `2026-10-05T13:15:00.000Z`）。
- 换算北京时间：**23:59 × 56 条**（当日截止语义）、21:15 × 6 条；与 D7 baseline 的 `T23:59:00+08:00` 为**同瞬时的不同写法**，未观察到语义偏差。
- D7 的"`date` 精度按当日截止处理"兜底逻辑未被本样例证伪或触发（样例无 `date` 精度样本）。

### 3.5 单课规模提示

- course-2 单课 54 条作业（同批创建、同一截止）、单课任务总量可达 62 条（54 作业 + 8 资源）。
- 生成侧无问题（90 任务毫秒级、确定性）；排程侧压力与 UI 展示属 B/C 域，仅记录实况。

## 4. 补全校准的路径（缺什么补什么）

1. **激活页/张估算（B 侧一行数据流）**：D2 解析完成后回填 `extent_value/extent_unit`（页数=页码定位数、张数=幻灯片定位数），`minutes_per_unit` 即从休眠转为生效；此后才有"按篇幅估算"可谈，**但数值本身仍需 §4.2 才能称校准**。
2. **数值校准（需用户反馈）**：上线后收集每类 ≥3 条实际耗时（D6 `FeedbackRecord`）→ `calibrate_estimates` 产 `type_estimate_factors` → 经 `TaskGenConfig` 生效（不改写用户自设耗时）。这是唯一能调整兜底时长的机制。
3. 若样例字段无法覆盖（如格式漂移），以新一轮只读会话补采；本批快照哈希已冻结，变更需走显式更新（测试会先报警）。
